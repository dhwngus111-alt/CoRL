# 2026-07-01 일일 업무 일지

## 1. antigravity (설계 및 운영 결정)

### 어떤 과정을 진행했는가

- HSP/MEP adaptive policy 학습 로그에서 나타난 불안정 현상을 검토했다.
  - value loss가 0 근처로 수렴한 뒤 entropy와 actor loss가 튀고 average reward가 무너지는 현상을 확인했다.
  - 이 현상은 단순한 의미의 supervised overfitting으로 단정하기보다, PPO actor update 불안정, entropy 압력, partner sampling 분포, reward shaping annealing, policy/value scale mismatch가 함께 작용할 수 있는 RL 학습 붕괴로 해석했다.
- HSP S2 adaptive policy와 MEP S2 adaptive policy의 하이퍼파라미터가 서로 분리되어야 한다고 정리했다.
  - HSP adaptive는 HSP paper/repo의 S2 설정을 따른다.
  - MEP adaptive는 MEP paper/original repo의 S2 adaptive 설정을 따른다.
- HSP adaptive 학습 설정을 최종 검토했다.
  - `N_ROLLOUT_THREADS=300`
  - `NUM_ENV_STEPS=100000000`
  - `REWARD_SHAPING_HORIZON=100000000`
  - `PPO_EPOCH=15`
  - `NUM_MINI_BATCH=1`
  - `HSP_S2_POPULATION_SIZE=36`
  - `entropy_coef=0.01`
  - Risky protocol 값: `EPISODE_LENGTH=200`, `P_SLIP=0.4`, `TIME_COST=-0.3`, `HANDOFF_SHAPING=1`, `SUBGOAL_DISABLE_STEPS=60`
- HSP의 `use_maxpool2d`는 paper 문구만 보면 max pooling을 쓰는 쪽으로 읽힐 수 있지만, HSP repo S2 실행 script에서는 `--use_maxpool2d`를 넘기지 않아 기본값 `False`로 동작하는 것을 확인했다.
  - 최종 결정: HSP repo 실행 기준을 따라 `use_maxpool2d=False` 유지.
- MEP adaptive 학습 설정을 MEP paper/original repo 기준으로 재검토했다.
  - MEP paper에서 명시한 값:
    - population size 5
    - beginner/middle/best checkpoint를 사용해 최종 population 구성
    - parallel environments 50
    - discount factor `gamma=0.99`
    - max gradient norm `0.1`
    - PPO clipping factor `0.05`
    - hidden layers 3
    - hidden size 64
    - convolution layers 3
    - filters 25
    - value function coefficient 0.1
    - prioritized sampling beta/alpha 계열 값 3
  - MEP repo 기준으로 확인한 값:
    - learning rate `8e-4`
    - critic learning rate `8e-4`
    - GAE lambda `0.98`
    - entropy coefficient `0.5`
    - PPO run timesteps `40000`
  - Risky protocol 값:
    - `EPISODE_LENGTH=200`
    - `P_SLIP=0.4`
    - `TIME_COST=-0.3`
    - `HANDOFF_SHAPING=1`
    - `SUBGOAL_DISABLE_STEPS=60`
- MEP reward shaping horizon은 원 논문 기본 5M 종료가 아니라, 사용자의 의도대로 전체 adaptive 학습 동안 `1 -> 0`으로 annealing되도록 유지하기로 결정했다.
  - 현재 MEP S2 기본 계산값은 population 15 기준 `NUM_ENV_STEPS=42600000`이다.
  - 따라서 `MEP_S2_REWARD_SHAPING_HORIZON=42600000`으로 전체 학습 기간에 걸쳐 shaping을 줄인다.
- MEP CNN의 kernel/padding/activation까지 original MEP TensorFlow 구현과 완전히 맞출지는 검토했지만 적용하지 않기로 했다.
  - paper에는 filters/layers 수는 명시되어 있으나 kernel/padding/activation 세부값은 명시되어 있지 않다.
  - 따라서 이번 범위에서는 `NUM_FILTERS=25`, `NUM_HIDDEN_LAYERS=3`, `SIZE_HIDDEN_LAYERS=64`의 실제 적용만 보장한다.

### 왜 그 과정이 필요한가

adaptive policy 학습은 fixed partner pool, PPO update scale, reward shaping schedule, architecture가 한 번에 얽힌다. HSP와 MEP의 adaptive stage를 같은 기본값으로 돌리면 어느 baseline이 어떤 논문/원본 repo 설정을 따랐는지 추적하기 어려워진다.

이번 정리는 다음을 보장하기 위한 것이다.

- HSP adaptive와 MEP adaptive의 하이퍼파라미터를 명시적으로 분리한다.
- paper에 명시된 값과 original repo에서만 확인되는 값을 구분한다.
- Risky protocol에서 의도적으로 달라진 값은 예외로 기록한다.
- 다음 학습 run에서 어떤 설정으로 돌렸는지 W&B/log와 일지에서 다시 검증할 수 있게 한다.

### 기존 환경인 HSP에서는 어떤 것을 사용하거나 수정했는가

- HSP algorithm code의 adaptive trainer/policy pool 구조를 그대로 사용한다.
- HSP S2 adaptive 학습은 `transplant/scripts/07_train_hsp_s2_risky.sh`를 통해 실행한다.
- HSP S2 기본값은 HSP paper/repo 기준으로 유지한다.
  - 300 rollout threads
  - 100M env steps
  - 100M reward shaping horizon
  - PPO epoch 15
  - mini-batch 1
  - S2 partner population 36
  - entropy coefficient 0.01
- HSP repo의 S2 실행 기준을 따라 `use_maxpool2d=False`를 유지한다.
- adaptive milestone checkpoint 저장을 위해 HSP algorithm code의 `trainer_pool.py`에 저장 hook을 사용한다.
  - Stage 2 adaptive trainer에만 적용된다.
  - `algorithm_name`이 `adaptive` 또는 `mep`인 경우만 적용된다.
  - `adaptive_agent_name`과 현재 trainer name이 일치하는 경우만 적용된다.

### 기존 환경인 risky에서는 어떤 것을 사용했는가

- 실제 dynamics, slip, time cost, subgoal disable, handoff shaping은 Risky env/transplant 설정을 따른다.
- 공통 Risky protocol:
  - `EPISODE_LENGTH=200`
  - `P_SLIP=0.4`
  - `TIME_COST=-0.3`
  - `SUBGOAL_DISABLE_STEPS=60`
- `SUBGOAL_DISABLE_STEPS=60`은 초 단위가 아니라 environment step 단위다.
- HSP adaptive와 MEP adaptive 모두 Risky adapter 위에서 같은 layout 세 개를 대상으로 실행한다.
  - `risky_dualpath_subgoal`
  - `risky_mixed_coordination_subgoal`
  - `risky_multipath_subgoal`

### MEP S2 adaptive architecture 반영

- MEP paper/original repo에서 확인한 architecture 관련 값이 실제 adaptive policy 생성 시점에 들어가도록 수정했다.
  - `NUM_HIDDEN_LAYERS=3`
  - `SIZE_HIDDEN_LAYERS=64`
  - `NUM_FILTERS=25`
- 수정 파일:
  - `MEP_transplant/scripts/02_train_mep_s2_risky.sh`
    - `MEP_S2_LAYER_N="${MEP_S2_LAYER_N:-3}"`
    - `MEP_S2_HIDDEN_SIZE="${MEP_S2_HIDDEN_SIZE:-64}"`
    - `CNN_LAYERS_PARAMS="${CNN_LAYERS_PARAMS:-25,3,1,1 25,3,1,1 25,3,1,1}"`
    - 실행 command에 `--layer_N "${MEP_S2_LAYER_N}"`, `--hidden_size "${MEP_S2_HIDDEN_SIZE}"` 추가
  - `transplant/train_risky_adaptive.py`
    - adaptive policy override field에 `hidden_size`, `layer_N`, `cnn_layers_params` 추가
    - `log_adaptive_policy_config()`에 같은 architecture field 추가
    - 학습 시작 시 `adaptive_policy_config mep_adaptive:` 로그에서 실제 적용값을 확인할 수 있게 했다.
- 이 변경은 population YAML의 `rnn_policy_config.pkl`에서 가져온 기존 architecture 값이 adaptive policy에 남는 문제를 막기 위한 것이다.

### 주의 사항

- `01_prepare_mep_s1_pool.py`는 최신 wandb run을 직접 고르지 않는다.
  - 이미 만들어진 `transplant/policy_pool/<layout>/mep/s1/`을 복사한다.
  - 최신 run 선택은 그 이전 extract 단계에서 결정된다.
- 현재 source pool은 handoff shaping 적용 run에서 온 것으로 확인했지만, 나중에 source pool을 다시 만들 경우 같은 검증을 반복해야 한다.
- MEP reward shaping horizon은 paper literal 5M이 아니라, 사용자의 의도에 따라 전체 학습 길이인 42.6M으로 유지한다.
- MEP CNN kernel/padding/activation까지 original MEP repo와 완전 동일하게 맞춘 것은 아니다.
  - paper에 명시된 filters/layers/hidden size만 이번 변경 범위에서 실제 적용되게 했다.
- HSP의 `use_maxpool2d=False`는 paper literal보다 HSP repo 실행 기준을 따른 결정이다.
- `SUBGOAL_DISABLE_STEPS=60`은 초 단위가 아니라 environment step 단위다.
