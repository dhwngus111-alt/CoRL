### 왜 그 과정이 필요한가

새 `risked_overcooked` repo의 최신 커밋은 기존 transplant가 기대하던 raw event schema와 일부 shaping logic을 바꿨다. 특히 새 env에는 raw event `subgoal_press`가 추가되었고, 이전 transplant 문서/코드는 `subgoal_activated` compatibility event를 직접 만들어 HSP hidden utility에 연결하는 구조였다.

따라서 단순히 repo만 교체하면 다음 문제가 생긴다.

- `transplant.hsp_hidden_utility` import 시 새 raw event `subgoal_press`가 unclassified event로 감지되어 실패한다.
- 평가에서 `time_cost=-0.3`이 들어가면 sparse score 비교가 time penalty에 오염될 수 있다.
- W&B project가 layout별로 분리되지 않으면 세 layout 결과가 한 project에 섞인다.
- run name 앞에 stage 번호가 없으면 W&B run 리스트에서 `01/03/05/07/08/09` 순서를 한눈에 보기 어렵다.

### 남은 주의 사항

- W&B project는 run 시작 시점에 결정되므로 이미 시작된 run은 중간에 project를 바꿀 수 없다.
- MEP S1을 layout별 project로 깨끗하게 남기려면 현재 run을 중단하고 다시 시작해야 한다.
- 학습은 `time_cost=-0.3`, 평가는 `time_cost=0`으로 의도적으로 다르다.
- `subgoal_press`는 raw event이고 log-only로 둔다.
- HSP hidden utility에서 subgoal 선호축은 계속 `subgoal_activated` compatibility event를 사용한다.
- `handoff_shaping`은 명시적으로 `HANDOFF_SHAPING=1`을 export하지 않는 한 MEP/HSP 학습 모두 false다.
