# 2026-06-30 일일 업무 일지

## 1. antigravity (설계 및 운영 결정)

### 어떤 과정을 진행했는가

- GAMMA 논문, 원본 GAMMA repo, `GAMMA_transplant`의 설정 차이를 다시 확인했다.
- GAMMA Risky baseline은 human/BC/SP/FCP held-out 없이 MEP-only source population으로 진행하기로 정리했다.
- VAE dataset은 MEP 8개에서 추출한 init/mid/final checkpoint 24개를 사용한다.
- VAE dataset 생성은 MEP 24개끼리 ordered pair 전체를 사용한다.
  - `24 x 24 = 576` policy pairs
  - `GAMMA_TOTAL_TRAJECTORIES=100000`은 pair별 균등 배분 때문에 실제 수집 목표가 `576 x 173 = 99648` trajectories로 내려간다.
- VAE train/validation split은 policy-level split이 아니라 HDF5 `train` group 안의 trajectory index split이다.
  - 70% trajectory: VAE parameter update
  - 30% trajectory: validation/checkpoint selection
- `test` HDF5 group은 원본 repo에서 held-out SP eval 용도에 가깝고, 현재 MEP-only Risky baseline에서는 필수 경로가 아니라고 판단했다.

### 왜 그 과정이 필요한가

GAMMA paper setting, GAMMA repo script/default, Risky transplant baseline setting이 서로 섞이면 재현성 기준이 흐려진다. 특히 repo argparse 기본값과 논문값이 다른 항목이 있어, baseline 기준을 "GAMMA 논문 설정을 Risky MEP-only protocol에 맞춰 적용"하는 것으로 명확히 했다.

확정한 기준은 다음과 같다.

- dataset collection:
  - `GAMMA_TOTAL_TRAJECTORIES=100000`
  - `N_ROLLOUT_THREADS=200`
  - `GAMMA_MAX_POLICY_PAIRS=0`
- VAE:
  - `GAMMA_VAE_EPOCH=500`
  - `GAMMA_VAE_LR=5e-4`
  - `GAMMA_DATASET_VALIDATION_RATIO=0.3`
  - `GAMMA_VAE_BATCH_SIZE=64`
  - `GAMMA_VAE_CHUNK_LENGTH=100`
  - `GAMMA_VAE_HIDDEN_SIZE=256`
  - `GAMMA_Z_DIM=16`
  - `GAMMA_WEIGHT_DECAY=1e-4`

### 기존 환경인 HSP에서는 어떤 것을 사용하거나 수정했는가

- HSP algorithm code나 HSP env는 수정하지 않았다.
- HSP repo의 human/held-out population 가정을 GAMMA Risky baseline에 그대로 가져오지 않았다.
- 기존 transplant/HSP pipeline에서 만들어 둔 MEP S1 결과를 GAMMA source population의 입력으로만 사용한다.

### 기존 환경인 risky에서는 어떤 것을 사용했는가

- Risky layout 3개를 GAMMA baseline 대상으로 사용한다.
  - `risky_dualpath_subgoal`
  - `risky_mixed_coordination_subgoal`
  - `risky_multipath_subgoal`
- Risky env adapter와 기존 transplant evaluation path를 그대로 사용한다.
- VAE dataset collection과 GAMMA S2 학습은 Risky env wrapper 위에서 수행한다.

### 검증/주의 사항

- `GAMMA_MAX_POLICY_PAIRS=0`은 pair 제한 없음이다.
  - full baseline에서는 0이 맞다.
  - 양수 값은 smoke/debug 용도로만 사용한다.
- `GAMMA_MEP_RUN_NAME=latest-run`은 코드가 여러 run 중 mtime 최신을 직접 찾는 것이 아니라, wandb의 `latest-run` symlink를 따른다.
  - 현재 latest-run을 source로 쓰는 것이 의도와 맞다고 확인했다.
- `02_create_gamma_dataset.sh`는 HDF5를 새로 쓰므로, 같은 layout의 기존 `dataset.hdf5`는 덮어써질 수 있다.
- 02가 끝나기 전 중단되면 partial HDF5가 남을 수 있다.
  - 재실행 전 파일 크기/mtime을 확인하고, 필요하면 해당 `dataset.hdf5`를 정리한 뒤 다시 시작한다.
- 03 VAE 학습은 아직 시작하지 않았다.
  - 다음 단계는 각 layout의 02 완료 확인 후 `03_train_gamma_vae.sh` 실행이다.
