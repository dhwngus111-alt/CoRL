# 2026-05-28

## Risky subgoal 실험 기본값 변경

### 배경

`risky_multipath_subgoal` 계열 HSP 실험에서 두 가지 환경 값을 바꾸기로 했다.

기존 의도:

- `G` subgoal interact 후 puddle `W` 비활성화 시간을 더 길게 둔다.
- 한 episode horizon을 줄여 HSP 학습 episode 길이를 짧게 가져간다.

최종 적용값:

```text
subgoal_disable_steps: 60
episode_length: 200
```

주의할 점은 기존 코드상 subgoal 비활성화 값이 30이 아니라 `20`으로 들어 있었다는 점이다. layout 파일과 transplant CLI 기본값 모두 `20`이었고, 이를 목표값 `60`으로 변경했다.

### 수정 내용

transplant 실험 기본값:

- `transplant/common.sh`
  - `EPISODE_LENGTH` 기본값을 `400`에서 `200`으로 변경했다.
  - `SUBGOAL_DISABLE_STEPS="${SUBGOAL_DISABLE_STEPS:-60}"`를 추가했다.
  - `COMMON_ARGS`에 `--subgoal_disable_steps "${SUBGOAL_DISABLE_STEPS}"`를 추가했다.
- `transplant/common.py`
  - `--subgoal_disable_steps` parser 기본값을 `20`에서 `60`으로 변경했다.
- `transplant/adapters/risky_overcooked_env.py`
  - `all_args.episode_length`가 없을 때 adapter fallback을 `400`에서 `200`으로 변경했다.
- `transplant/build_policy_configs.py`
  - `--episode-length` 기본값을 `400`에서 `200`으로 변경했다.

Risky layout:

다음 layout들의 `"subgoal_disable_steps": 20`을 모두 `60`으로 변경했다.

```text
risky_mixed_coordination
risky_shortcuts
risky_spiral_subgoal
risky_multipath_subgoal
risky_tree_subgoal
risky_multipath_subgoal_tomato
risky_passing
```

Risky engine:

- `risky/src/risky_overcooked_py/mdp/overcooked_mdp.py`
  - `_subgoal_timers_activated_this_step` set을 추가했다.
  - subgoal activation이 일어난 같은 transition의 end tick에서 새 timer가 바로 1 감소하지 않도록 했다.

이 보정이 필요한 이유:

기존 transition 순서는 `resolve_interacts()`에서 timer를 `subgoal_disable_steps`로 설정한 뒤, transition 끝에서 `_tick_subgoal_timers()`를 호출한다. 따라서 `subgoal_disable_steps=60`이어도 interact 직후 관측되는 timer가 `59`가 되었다. 실험 의미상 "누른 직후 60 step 비활성화"가 더 자연스럽기 때문에, 같은 step에 새로 activation된 water tile은 그 step의 tick에서 제외하도록 바꿨다.

원본 Risky env의 전역 fallback은 그대로 둔다.

```python
kwargs.get("subgoal_disable_steps", 20)
```

즉 직접 `OvercookedGridworld`를 layout 없이 만드는 특수 경로까지 전역 변경하지는 않았다. 실험 경로는 layout 또는 transplant CLI를 통해 `60`을 받는다.

### 진행 중 실험 영향

실행 중인 Python process는 시작할 때 CLI args와 parser 기본값을 메모리에 들고 있으므로, 파일을 수정해도 hot reload되지 않는다.

확인 당시 진행 중이던 HSP S1 run은 다음 값을 명시적으로 가지고 있었다.

```text

episode_length: 400
time_cost: -0.3
num_env_steps: 10000000
```

따라서 오늘 변경한 `episode_length=200`, `subgoal_disable_steps=60`은 새로 시작하는 run부터 적용된다.

### 해석 메모

두 실행 모두 `transplant/scripts/03_train_hsp_s1_risky.sh`를 사용한다.

이 script는 내부에서 다음을 수행한다.

1. `transplant/common.sh`를 source해서 공통 인자를 구성한다.
2. 현재 layout/episode length 기준으로 policy config를 생성한다.
3. `transplant.train_risky_hsp_s1_bundle`을 실행한다.
4. `--use_hsp --random_index --share_policy`를 켠다.
5. W&B bundle run 하나에 seed 1부터 `SEED_MAX`까지 묶어 로깅한다.

`r[...]` spec은 command line에 그대로 들어가지만, 실제 각 seed 학습 직전에 `sample_hsp_weights()`에서 숫자로 샘플링된다. 완전히 같은 숫자 weight를 재현하려면, spec이 아니라 샘플링 완료 후의 `all_args.w0/w1` 값을 기록해서 고정해야 한다.
