## MEP S1 final GIF logging 추가

### 배경

HSP S1에서는 각 seed 학습이 끝난 뒤 W&B seed 패널에 final GIF가 올라가도록 hook을 추가해 둔 상태였다. 반면 MEP S1은 한 run 안에서 `mep1..mepN` population을 학습하기 때문에, 학습 종료 후 행동을 바로 비교할 수 있는 GIF 패널이 없었다.

요구사항은 MEP S1 학습 종료 시점에 같은 W&B run 안에 GIF 전용 패널 섹션 하나를 만들고, 최종 MEP population에서 랜덤 ordered pair episode 10개를 렌더링해 올리는 것이었다. 또한 앞으로 생성되는 transplant Risky GIF는 기존보다 1/3 속도로 재생되도록 저장 duration을 바꾸기로 했다.

### 수정 내용

`transplant.common.add_risky_overcooked_args(mode="adaptive")`에 `--mep_final_gif_episodes` 인자를 추가했다. 기본값은 `0`이고, MEP S1 script에서만 기본 `10`을 넘기도록 했다.

`transplant/scripts/01_train_mep_s1_risky.sh`에는 다음 기본값과 CLI 전달을 추가했다.

```bash
MEP_FINAL_GIF_EPISODES="${MEP_FINAL_GIF_EPISODES:-10}"
--mep_final_gif_episodes "${MEP_FINAL_GIF_EPISODES}"
```

`transplant/train_risky_adaptive.py`에는 Stage 1 MEP일 때만 final render env를 생성하는 helper를 추가했다.

- `mep_final_gif_episodes <= 0`이면 생성하지 않는다.
- `algorithm_name == "mep"`이고 `stage == 1`일 때만 동작한다.
- render env는 `use_render=True`, `random_index=False`, `render_gif_subdir="final_mep_s1"`로 만든다.
- W&B 사용 시에는 `wandb.run.dir` 아래에 GIF가 저장되도록 `init_wandb()` 이후 render env를 만든다.

`transplant/runners/risky_overcooked_runner.py`에는 Stage 1 MEP 학습 종료 후 final GIF hook을 추가했다.

- `super().train_mep()` 종료 직후 `_log_stage1_mep_final_gifs()`를 호출한다.
- 최종 `self.trainer.population`에서 `mep_adaptive`를 제외한 policy 이름을 모은다.
- 학습 seed 기반 RNG로 ordered pair를 샘플링한다.
- 가능한 ordered pair 수가 요청 GIF 수보다 많으면 중복 없이 뽑고, 부족하면 중복을 허용한다.
- W&B key는 하나의 최상위 섹션에 기록한다.

```text
stage1_mep_final_gifs/local_env_step
stage1_mep_final_gifs/gif_01_<agent0>_vs_<agent1>
...
stage1_mep_final_gifs/gif_10_<agent0>_vs_<agent1>
```

`transplant/adapters/risky_overcooked_env.py`의 GIF 저장 duration은 다음처럼 변경했다.

```python
imageio.mimsave(output_path, frames, duration=0.15)
```

기존 `0.05`에서 `0.15`로 3배 늘렸기 때문에, 앞으로 새로 생성되는 transplant Risky GIF는 기존 대비 1/3 속도로 재생된다.

### HSP / Risky 관점

HSP algorithm code에서 사용한 것:

- HSP `PolicyPool` / `EvalPolicy`의 `set_map_ea2p`, `register_control_agent`, `policy.step(...)` 흐름
- HSP vector env wrapper의 `get_last_render_gif_paths()` 수집 방식
- MEP Stage 1의 shared population runner 구조와 `trainer.population` 관리 방식

HSP env에서 사용하지 않은 것:

- HSP Overcooked env dynamics
- HSP env renderer
- HSP env shaped-info/event 이름

Risky 쪽에서 기준으로 삼은 것:

- `RiskyOvercooked` adapter의 transition, reward, event bookkeeping
- adapter의 `use_render=True` trajectory 기록 및 GIF 저장 경로
- Risky render frame 생성 로직

### 주의 사항

이미 실행 중인 Python process에는 이번 hook과 GIF duration 변경이 hot reload되지 않는다. MEP S1 final GIF logging과 1/3 속도 GIF 저장은 패치 이후 새로 시작한 run부터 적용된다.

## Risky → HSP hidden utility 픽업 이벤트 매핑 수정

### 배경

Risky env의 raw `event_infos`에는 `onion_pickup`, `tomato_pickup`, `dish_pickup`, `soup_pickup`처럼 object 단위 pickup 여부만 들어 있고, 해당 object가 카운터 `X`, 디스펜서 `O/T/D`, 냄비 `P` 중 어디서 왔는지는 들어 있지 않았다.

기존 transplant 매핑은 이 raw pickup event를 바로 HSP hidden utility category로 변환했다.

```python
"onion_pickup" -> "pickup_onion_from_O"
"tomato_pickup" -> "pickup_tomato_from_T"
"dish_pickup" -> "pickup_dish_from_D"
"soup_pickup" -> "pickup_soup_from_X", "SOUP_PICKUP"
```

이 때문에 카운터에서 object를 집은 협동 pass 행동이 디스펜서 pickup처럼 기록되거나, soup pickup이 counter pickup과 pot pickup으로 동시에 기록되는 문제가 있었다.

추가로 Risky 코드상 tomato dispenser `T` pickup은 `log_object_pickup()` 호출이 빠져 있어, raw `tomato_pickup`만 믿으면 `pickup_tomato_from_T`도 누락될 수 있는 상태였다.

### 수정 내용

`transplant/hsp_hidden_utility.py`에서 모호한 pickup direct mapping 4개를 제거했다.

- `onion_pickup`
- `tomato_pickup`
- `dish_pickup`
- `soup_pickup`

`drop`, `potting`, `delivery`, `risked`, `handoff`, `useful_dish_pickup`처럼 source ambiguity가 없는 매핑은 그대로 유지했다.

`transplant/adapters/risky_overcooked_env.py`에는 source-specific pickup 보정 helper를 추가했다.

핵심 흐름:

1. `base_env.step(...)` 호출 직전에 `prev_state = self._state_snapshot()`을 저장한다.
2. Risky env step 이후 `event_infos`를 기존 방식으로 HSP hidden utility dict에 매핑한다.
3. vector 변환 전에 `_apply_source_specific_pickups(prev_state, next_state, joint_action, step_shaped_info)`를 호출한다.
4. helper는 base env player index 기준으로 `joint_action`, `prev_state.players`, `next_state.players`를 함께 본다.
5. agent가 `Action.INTERACT`를 했을 때만 이전 위치/방향으로 전방 타일을 계산하고, 실제 held object 변화까지 확인해 category를 채운다.

추가된 category 판별:

- counter `X`
  - onion -> `pickup_onion_from_X`
  - tomato -> `pickup_tomato_from_X`
  - dish -> `pickup_dish_from_X`
  - soup -> `pickup_soup_from_X`
- dispenser
  - `O` + onion -> `pickup_onion_from_O`
  - `T` + tomato -> `pickup_tomato_from_T`
  - `D` + dish -> `pickup_dish_from_D`
- pot
  - `P` + dish에서 soup로 전이 -> `SOUP_PICKUP`

### HSP / Risky 관점

HSP algorithm code에서 사용한 것:

- hidden utility vector order와 `w0/w1` weight dimension 구조
- HSP S1이 기대하는 source-specific category 이름
  - `pickup_onion_from_X`
  - `pickup_onion_from_O`
  - `pickup_soup_from_X`
  - `SOUP_PICKUP`

HSP env에서 사용하지 않은 것:

- HSP Overcooked env의 transition
- HSP env의 `shaped_info_by_agent`
- HSP env 내부 event 판정 로직

Risky 쪽에서 기준으로 삼은 것:

- 실제 state transition
- player position/orientation
- `Action.INTERACT`
- `base_mdp.get_terrain_type_at_pos(...)`
- `prev_state`와 `next_state`의 held object 변화

transplant에서 담당한 것:

- Risky raw pickup event가 잃어버린 source 정보를 adapter 단에서 복원
- HSP hidden utility category dict/vector로 변환
- raw Risky source와 HSP env source를 직접 수정하지 않고 boundary에서 보정

### 주의 사항

이번 수정 이후 기존 HSP S1 학습 결과는 pickup hidden reward가 잘못 들어간 기준으로 만들어진 것이다. source-specific pickup category가 학습 reward에 영향을 주는 실험을 다시 비교하려면 HSP S1부터 재학습하는 것이 맞다.

또한 `soup_pickup`은 더 이상 `pickup_soup_from_X`와 `SOUP_PICKUP`을 동시에 올리지 않는다. pot에서 뜬 soup와 counter에서 받은 soup는 이번 수정 이후 의미가 분리된다.
