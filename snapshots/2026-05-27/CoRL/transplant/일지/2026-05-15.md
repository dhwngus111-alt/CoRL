- HSP baseline을 Risky Overcooked의 risky_multipath layout에 이식하기 위한 transplant 패키지를 구현했다.
- 사용자의 요청대로 원본 /home/isl_jhoh/CoRL/HSP 와 /home/isl_jhoh/CoRL/overcooked 는 수정하지 않았다.
- 새 코드, 설정, 실행 스크립트, 결과물은 모두 /home/isl_jhoh/CoRL/transplant 아래에만 두었다.

목적
- 새로운 실험 환경은 /home/isl_jhoh/CoRL/overcooked 안에 있다.
- 이 환경은 기존 Overcooked 환경에 risk 요소인 물웅덩이와 subgoal이 추가된 개선 환경이다.
- 현재 연구의 목표는 새롭게 개선된 Overcooked 환경에서 새로운 모델의 성능을 평가하는 것이다.
- 논문에 들어갈 baseline 중 하나로 HSP가 포함되어 있다.
- 따라서 해야 할 일은 baseline인 HSP를 새로운 환경 /home/isl_jhoh/CoRL/overcooked 에서 실행하고 평가할 수 있도록 연결하는 것이다.
- 현재 v1 목표는 전체 Risky layout 전체가 아니라 risky_multipath layout 하나에 대해 HSP 실행/평가 환경을 구축하는 것이다.

목적과 이번 구현의 대응
- HSP 원본 알고리즘은 /home/isl_jhoh/CoRL/HSP 에 그대로 두고, transplant에서 import해서 사용하도록 했다.
- 새 Risky Overcooked 환경은 /home/isl_jhoh/CoRL/overcooked/src/risky_overcooked_py 에 그대로 두고, transplant adapter에서 import해서 사용하도록 했다.
- transplant/adapters/risky_overcooked_env.py가 HSP runner와 Risky Overcooked 환경 사이의 중간자 역할을 한다.
- HSP가 내는 action index를 Risky Overcooked action으로 바꾸고, Risky env의 obs/reward/info를 HSP runner가 이해하는 형식으로 포장한다.
- 이 구현은 지금 단계에서 risky_multipath 하나를 대상으로 HSP baseline을 학습/추출/평가하는 전체 흐름을 만들기 위한 것이다.

전체 방향
- HSP 알고리즘/runner는 원본 HSP 코드를 그대로 import해서 사용한다.
- Risky Overcooked 환경도 원본 overcooked/src/risky_overcooked_py 를 그대로 import해서 사용한다.
- transplant가 두 코드 사이의 adapter, entrypoint, policy config, scripts, outputs 역할을 맡는다.

주요 구현 파일
- transplant/bootstrap.py
  - HSP, Risky Overcooked, transplant compat 경로를 sys.path에 추가한다.
  - HSP의 POLICY_POOL 기본 경로를 transplant/policy_pool로 잡는다.

- transplant/adapters/risky_overcooked_env.py
  - HSP runner가 기대하는 Overcooked env API를 Risky Overcooked 위에 구현했다.
  - reset() -> obs, share_obs, available_actions 형식을 맞췄다.
  - step() -> obs, share_obs, reward, done, info, available_actions 형식을 맞췄다.
  - HSP action index 0..5를 Risky Action.INDEX_TO_ACTION으로 변환한다.
  - risky_multipath의 lossless obs를 HSP PPO obs로 사용한다.
  - share_obs는 두 agent obs를 concat해서 centralized critic 입력으로 만든다.
  - available_actions는 v1에서 2 x 6 전체 action 허용 mask로 둔다.
  - Risky event_infos를 HSP-style 28차원 ep_category_r_by_agent로 매핑한다.
  - HSP hidden utility weight는 기존 방식대로 21 event weight + sparse weight = 22차원으로 유지했다.
  - Risky risk/slip/handoff event는 info에 보존하되 HSP hidden utility 핵심 21차원에는 직접 넣지 않았다.

- transplant/train_risky_hsp.py
  - HSP S1 biased policy 학습용 entrypoint.
  - 원본 HSP train_overcooked_hsp.py 구조를 따르되 env 생성만 Risky adapter로 교체했다.

- transplant/train_risky_adaptive.py
  - MEP S1 및 HSP S2 adaptive 학습용 entrypoint.
  - 원본 HSP adaptive training flow를 유지하고, env 생성과 output path만 transplant 기준으로 바꿨다.
  - HSP의 population runner가 envs.load_policy()를 호출하므로 adaptive 쪽은 n_rollout_threads=1이어도 ShareSubprocVecEnv를 사용하게 했다.
  - 원본 HSP S2 loop에 wandb.log가 직접 호출되는 지점이 있어, use_wandb=False일 때도 wandb disabled mode를 초기화하도록 했다.

- transplant/eval_risky_hsp.py
  - population yaml의 두 policy를 Risky env에서 평가하는 entrypoint.
  - HSP evaluate_with_multi_policy() 흐름을 그대로 탄다.

- transplant/build_policy_configs.py
  - risky_multipath용 mlp/rnn policy_config.pkl을 생성한다.
  - obs shape는 (7, 6, 28), share_obs shape는 (7, 6, 56), action space는 Discrete(6) 기준이다.
  - HSP CNN 기본 conv 설정이 작은 Risky grid에서 깨져서, HSP Overcooked script에서 쓰던 padded CNN 설정을 기본으로 넣었다:
    32,3,1,1 64,3,1,1 32,3,1,1
  - MEP S1 train.yml도 생성한다.

- transplant/scripts/
  - 00_check_env.sh: import, policy config 생성, env reset/step smoke check.
  - 01_train_mep_s1_risky.sh: MEP S1 학습.
  - 02_extract_mep_s1_risky.py: MEP S1 checkpoint를 policy_pool 형식으로 추출.
  - 03_train_hsp_s1_risky.sh: HSP S1 biased policy 학습.
  - 04_extract_hsp_s1_risky.py: HSP S1 separated actor checkpoint 추출.
  - 05_eval_events_risky.sh: HSP S1 pair event 평가.
  - 06_greedy_select_risky.py: event 로그 기반 greedy selection 후 HSP S2 train.yml 생성.
  - 07_train_hsp_s2_risky.sh: HSP S2 adaptive 학습.
  - 08_extract_hsp_s2_risky.py: HSP S2 adaptive checkpoint 추출 및 eval.yml 생성.
  - 09_eval_hsp_risky.sh: 최종 HSP adaptive 평가.

- transplant/common.sh
  - 공통 경로, python, layout, p_slip, horizon, thread, seed, step 수를 관리한다.
  - 기본 Python은 /home/isl_jhoh/miniconda3/envs/corl/bin/python이 있으면 사용하도록 했다.
  - SMOKE=1 모드를 지원해서 짧은 wiring test를 할 수 있다.

- transplant/compat/
  - 원본 HSP가 import하는데 현재 corl env에 없던 경량 dependency를 transplant-local shim으로 보완했다.
  - tensorboardX SummaryWriter fallback.
  - slackweb no-op fallback.
  - icecream.ic fallback.
  - 원본 HSP 코드를 수정하지 않기 위한 우회 계층이다.

- 하지만 hsp/s2/train.yml은 smoke에서 --k 1로 생성한 상태일 수 있다.
- full run을 할 때는 HSP S1을 seed 36개 등 원하는 수만큼 학습/추출한 뒤, 반드시 다음을 다시 실행해야 한다:
  python transplant/scripts/06_greedy_select_risky.py --layout risky_multipath --k 18
- full run에서는 common.sh의 NUM_ENV_STEPS, N_ROLLOUT_THREADS, EVAL_EPISODES, SEED_MAX 등을 실제 실험 규모로 키워야 한다.

현재 구현의 범위
- v1은 risky_multipath layout만 지원하도록 adapter에서 명시적으로 제한했다.
- action mask는 모든 6개 action 허용으로 시작했다.
- Risky 고유 risk/slip event는 logging/info에 보존하지만 HSP hidden utility selection 핵심 21차원에는 직접 포함하지 않았다.
- 추후 다른 Risky layout으로 확장하려면 adapter의 layout 제한, p_slip/default config, event logging 확장, script 변수 LAYOUT 사용을 점검하면 된다.
