# v1 2026-05-18 HSP-Risky 연결 상태 기록

## 요약

`06_greedy_select_risky.py`의 fallback selection을 제거했다.

이제 HSP S1 event 평가 결과가 없거나, greedy selection에 필요한 event vector 수가 `k`보다 적으면 `hsp/s2/train.yml`을 만들지 않고 즉시 중단한다.

## 배경

이전 v0 상태에서는 event log가 비어 있으면 `hsp/s1/eval.yml`에서 앞쪽 run을 읽어 첫 `k`개를 임시 선택하는 fallback이 있었다.

이 방식은 `EVAL_EPISODES < N_EVAL_ROLLOUT_THREADS` 같은 설정 문제로 실제 평가 episode가 0번 실행된 경우에도 pipeline이 계속 진행되는 문제가 있다. 특히 `selected runs: [1, 2, ..., 18]` 같은 출력이 실제 greedy diversity selection 결과처럼 보일 수 있다.

## 결정 사항

- event log가 없으면 selection을 중단한다.
- event vector 수가 `k`보다 적어도 selection을 중단한다.
- fallback으로 앞 run을 고르는 동작은 사용하지 않는다.

## 현재 동작

`06_greedy_select_risky.py`는 `transplant/biased_eval/<layout>/eval_hsp*.txt`에서 raw metric dict를 읽어 run별 Risky event vector를 만든다.

event vector가 하나도 없으면 다음 메시지로 실패한다.

```text
error: no event logs found for greedy selection. Run 05_eval_events_risky.sh with EVAL_EPISODES >= N_EVAL_ROLLOUT_THREADS first.
```

event vector 수가 `k`보다 적으면 다음 형태로 실패한다.

```text
error: only <n> event vectors found, but k=<k>. Re-run event evaluation for all HSP S1 candidates before selecting policies.
```

## 검증

- `python -m py_compile transplant/scripts/06_greedy_select_risky.py` 통과.
- 빈 eval 디렉터리를 넘겼을 때 `hsp/s2/train.yml`을 만들지 않고 즉시 실패하는 것을 확인.

## 주의 사항

- HSP S1 event 평가는 `EVAL_EPISODES >= N_EVAL_ROLLOUT_THREADS` 조건을 만족해야 한다.
- 빠른 확인용으로는 `N_EVAL_ROLLOUT_THREADS=1 EVAL_EPISODES=1`을 사용할 수 있다.
- 기본 eval thread 4개를 유지하려면 최소 `EVAL_EPISODES=4` 이상이 필요하다.
