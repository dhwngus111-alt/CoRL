# v3 2026-05-27 Risky → HSP hidden utility pickup source 매핑 구조

## 요약

이번 버전은 Risky env의 raw pickup event를 HSP hidden utility category로 옮길 때, counter/dispenser/pot source가 섞이던 문제를 정리한다.

핵심 결정은 Risky 원본 source와 HSP env source를 수정하지 않고, transplant adapter가 매 step의 `prev_state -> next_state` 전이를 직접 검사해 source-specific HSP category를 채우는 것이다.

이 구조에서 Risky raw `event_infos`는 여전히 비모호 event의 기준으로 사용하지만, `onion_pickup`, `tomato_pickup`, `dish_pickup`, `soup_pickup`은 hidden utility category로 직접 매핑하지 않는다.

## 배경

Risky `EVENT_TYPES`의 pickup event는 다음처럼 object pickup 여부만 표현한다.

```text
onion_pickup
tomato_pickup
dish_pickup
soup_pickup
```

반면 HSP hidden utility category는 pickup source를 구분한다.

```text
pickup_onion_from_X
pickup_onion_from_O
pickup_tomato_from_X
pickup_tomato_from_T
pickup_dish_from_X
pickup_dish_from_D
pickup_soup_from_X
SOUP_PICKUP
```

기존 transplant 매핑은 Risky raw pickup을 바로 HSP category로 넣었기 때문에 다음 문제가 있었다.

- counter `X`에서 onion을 받아도 `pickup_onion_from_O`로 기록됨.
- counter `X`에서 tomato를 받아도 `pickup_tomato_from_T`로 기록됨.
- counter `X`에서 dish를 받아도 `pickup_dish_from_D`로 기록됨.
- soup는 counter pickup과 pot pickup이 동시에 올라가 의미가 섞임.
- Risky의 tomato dispenser `T` pickup은 raw `tomato_pickup` logging이 빠져 있어 raw event만으로는 더 위험함.

## 전체 흐름

1. HSP algorithm code가 action을 낸다.
2. `RiskyOvercooked.step(...)`이 action index를 Risky `Action`으로 변환한다.
3. `self.agent_idx == 1`이면 adapter가 base env 내부 순서에 맞춰 `joint_action`을 swap한다.
4. adapter가 `base_env.step(...)` 직전에 `prev_state`를 deepcopy로 저장한다.
5. Risky env가 실제 transition을 수행하고 `next_state`, reward, `mdp_info["event_infos"]`를 반환한다.
6. `risky_events_to_hsp_category_info(...)`가 비모호 Risky raw event를 HSP hidden utility category dict로 변환한다.
7. adapter가 `prev_state`, `next_state`, `joint_action`, 전방 terrain을 비교해 source-specific pickup category를 추가한다.
8. `shaped_info_to_array(...)`가 category dict를 `(2, 29)` vector로 변환한다.
9. HSP hidden reward 계산은 이 vector와 `w0/w1`을 dot product해서 수행된다.

## 사용하는 것 / 사용하지 않는 것

- HSP algorithm code에서 사용하는 것:
  - hidden utility vector와 `w0/w1` weight 구조
  - HSP S1이 기대하는 source-specific category 이름
  - 기존 runner/trainer/policy 흐름

- HSP env에서 사용하지 않는 것:
  - HSP Overcooked env transition
  - HSP env의 `shaped_info_by_agent`
  - HSP env 내부 event logging 구현

- Risky env에서 기준으로 삼는 것:
  - 실제 MDP transition
  - `EVENT_TYPES` raw event
  - `Action.INTERACT`
  - player position/orientation
  - terrain type `X/O/T/D/P`
  - 이전/다음 state의 held object 변화

- transplant에서 담당하는 것:
  - Risky raw event를 HSP hidden utility schema로 변환
  - source-specific pickup category 복원
  - category vector 누적과 info dict logging

## event / feature / log 기준

비모호 Risky raw event는 `RISKY_TO_HSP_CATEGORY`에서 바로 변환한다.

예:

```text
onion_drop -> put_onion_on_X
potting_onion -> PLACEMENT_IN_POT, potting_onion
soup_delivery -> delivery
tomato_risked -> tomato_risked
tomato_handoff -> tomato_handoff
```

모호한 pickup raw event는 더 이상 직접 변환하지 않는다.

```text
onion_pickup
tomato_pickup
dish_pickup
soup_pickup
```

대신 adapter가 다음 source-specific category를 채운다.

```text
X + onion  -> pickup_onion_from_X
O + onion  -> pickup_onion_from_O
X + tomato -> pickup_tomato_from_X
T + tomato -> pickup_tomato_from_T
X + dish   -> pickup_dish_from_X
D + dish   -> pickup_dish_from_D
X + soup   -> pickup_soup_from_X
P + dish -> soup transition -> SOUP_PICKUP
```

## 결정 사항

### 결정 1: raw pickup event를 direct mapping에서 제거한다

`onion_pickup`, `tomato_pickup`, `dish_pickup`, `soup_pickup`은 HSP source-specific category에 직접 대응하지 않는다.

이유:

- raw event에는 source 정보가 없다.
- direct mapping을 유지하면 counter pickup이 dispenser pickup으로 오판된다.
- soup pickup은 counter와 pot 의미가 동시에 올라가는 중복 오류가 생긴다.

### 결정 2: adapter가 transition context로 source를 복원한다

source-specific pickup은 `prev_state`, `next_state`, `joint_action`, terrain type을 함께 보고 판단한다.

이유:

- Risky env 원본 source를 수정하지 않을 수 있다.
- HSP env의 `shaped_info_by_agent`에 의존하지 않아도 된다.
- tomato dispenser `T`처럼 raw logging이 빠진 경우도 held object transition으로 감지할 수 있다.

### 결정 3: base env 내부 player index 기준을 사용한다

보정 helper는 이미 swap이 끝난 `joint_action`과 `prev_state.players`, `next_state.players`의 같은 index를 사용한다.

이유:

- transplant adapter는 `self.agent_idx == 1`일 때 외부 agent order와 base env order를 바꾼다.
- source-specific event는 Risky env 내부 transition 기준으로 계산되어야 한다.
- 외부 observation/reward order를 기준으로 보정하면 agent별 category가 뒤집힐 수 있다.

### 결정 4: Risky source와 HSP env source는 수정하지 않는다

이번 변경은 transplant 계층에만 둔다.

이유:

- Risky env가 실제 transition source of truth다.
- HSP env는 이번 Risky 실험의 dynamics source가 아니다.
- boundary adapter에서 의미 변환을 처리하는 것이 유지보수와 실험 재현성에 더 안전하다.

## 이전 버전과 달라진 점

- v2는 MEP Stage 1 full run과 policy pool 생성 구조를 정리했다.
- v3는 HSP hidden utility event feature 중 pickup source ambiguity를 정리했다.
- 이전 구현에서는 Risky raw pickup event를 HSP category에 직접 매핑했다.
- 현재 구현에서는 비모호 event만 direct mapping하고, pickup source category는 adapter transition context로 채운다.

## 주의 사항

- 기존 HSP S1 결과는 잘못된 pickup hidden reward 기준으로 학습되었을 수 있다. 이번 수정 후 hidden utility 비교를 하려면 HSP S1 재학습이 필요하다.
- `soup_pickup`은 더 이상 `pickup_soup_from_X`와 `SOUP_PICKUP`을 동시에 올리지 않는다.
- 기본 Python 환경에는 일부 runtime dependency가 없으므로 targeted unittest는 `corl` env에서 실행하는 것이 기준이다.
- Risky `EVENT_TYPES`와 HSP hidden utility category 이름은 역할이 다르다. Risky raw event 이름을 HSP env shaped-info 이름과 같은 것으로 해석하면 안 된다.
