## HSP S1 final GIF 생성 버그 수정

### 배경

HSP S1 full run에서 각 seed policy pair 학습이 끝난 뒤 W&B에 GIF 3개가 바로 올라와야 했지만, 실제 run에서는 seed가 종료되어도 GIF가 생성되지 않았다.

확인 결과 `03_train_hsp_s1_risky.sh`는 `--hsp_final_gif_episodes 3`을 넘기고 있었고, W&B config에도 `hsp_final_gif_episodes: 3`이 기록되어 있었다. 문제는 HSP parser에서 `--share_policy`가 `store_false`로 정의되어 있어 HSP S1이 shared runner가 아니라 separated runner 경로를 탄다는 점이었다.

기존 final GIF hook은 `RiskyOvercookedRunner` shared runner에만 있었고, 실제 HSP S1이 사용하는 `RiskySeparatedOvercookedRunner`에는 `final_render_envs`를 사용하는 코드가 없었다.

### 수정 내용

`transplant/runners/risky_overcooked_separated_runner.py`에 separated policy 구조용 final render hook을 추가했다.

수정한 동작:

- `config["final_render_envs"]`를 runner에 저장한다.
- seed 학습이 `super().run()`으로 끝난 직후 final GIF hook을 호출한다.
- agent별 separated trainer 구조에 맞춰 `self.trainer[agent_id].policy.act(...)`를 deterministic mode로 호출한다.
- `hsp_final_gif_episodes` 개수만큼 render env를 굴리고, wrapper의 `get_last_render_gif_paths()`에서 GIF 경로를 수집한다.
- W&B에는 `seedXX/final_gifs/step_10000000_gif_{1..3}` 형태로 `wandb.Video(..., format="gif")`를 기록한다.

GIF 저장 위치:

```text
transplant/results/RiskyOvercooked/risky_multipath/mappo/hsp-S1/runN/gifs/risky_multipath/final_hsp_s1/env_{0..2}/.../*.gif
```

W&B key:

```text
seedXX/final_gifs/step_10000000_gif_1
seedXX/final_gifs/step_10000000_gif_2
seedXX/final_gifs/step_10000000_gif_3
```

## time_cost 비교용 HSP S1 동시 실행

### 목적

HSP S1에서 `time_cost` 값을 바꿨을 때 학습 reward curve, sparse reward attribution, seed별 GIF 행동이 어떻게 달라지는지 W&B에서 비교하기 위해 네 가지 설정을 동시에 실행했다.

비교 대상:

```text
time_cost = 0.0
time_cost = -0.1
time_cost = -0.2
time_cost = -0.3
```

### 실행 상태 확인

확인 시점 기준 네 개 HSP S1 process가 모두 실행 중이었다.

```text
time_cost  0.0 -> PID 2794671
time_cost -0.1 -> PID 2810816
time_cost -0.2 -> PID 2902253
time_cost -0.3 -> PID 2687482
```

공통 실행 인자:

```text
seed_max: 36
num_env_steps per seed pair: 10000000
n_rollout_threads: 100
hsp_final_gif_episodes: 3
```

GPU 배치:

```text
GPU 0 -> time_cost  0.0
GPU 3 -> time_cost -0.3
GPU 3 -> time_cost -0.2
GPU 5 -> time_cost -0.1
```

### 해석과 주의 사항

이번 동시 실행은 W&B 비교용이다. W&B run은 내부 run id로 구분되므로 run name이 같아도 logging이 서로 덮어쓰이지 않는다.

반면 local filesystem에서는 같은 `hsp-S1` root 아래 `runN`이 배정되므로, 여러 HSP S1 process가 동시에 돌면 seed별 local run directory가 서로 섞일 수 있다.

따라서 이번 결과는 다음 용도로만 사용한다.

```text
사용 가능: W&B reward curve / hidden utility table / final_gifs 비교
사용 금지: 04_extract_hsp_s1_risky.py로 최종 S2 policy pool 추출
```

최종으로 사용할 `time_cost` 설정을 고른 뒤에는 해당 설정만 단독으로 다시 실행하고, 그 clean run에서 extract를 진행한다.

### HSP / Risky 관점

HSP algorithm code에서 사용하는 것:

- HSP separated runner/trainer/policy/buffer 구조
- HSP S1 seed별 biased policy pair 학습 절차
- HSP parser의 `--share_policy` / `--use_recurrent_policy` flag semantics

HSP env에서 사용하지 않는 것:

- HSP Overcooked env의 dynamics, event, shaped-info schema
- HSP env renderer

Risky env에서 기준으로 삼는 것:

- Risky Overcooked transition, reward, slip, event bookkeeping
- transplant adapter가 생성하는 Risky render frame과 GIF 저장 경로

transplant에서 담당한 것:

- Risky env를 HSP separated runner가 사용할 수 있는 vector env로 감싸기
- HSP S1 final GIF 생성과 W&B 업로드 연결
- W&B 비교용 time_cost별 실행 상태 확인
