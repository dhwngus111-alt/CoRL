# 2026-06-26 일일 업무 일지

## GAMMA Risky MEP-only 이식 기록

## 요약

이번 문서는 GAMMA를 Risky Overcooked 위에서 baseline으로 돌리기 위해 현재까지 결정하고 구현한 구조를 정리한다.

핵심 방향은 다음과 같다.

- 원본 `GAMMA/`는 최대한 건드리지 않고, 이식 코드는 `GAMMA_transplant/` 아래에 둔다.
- GAMMA baseline은 human data 없이 **MEP-generated population + GAMMA**로 구성한다.
- source population은 `transplant/results`에 있는 MEP S1 checkpoint에서 가져오되, `mep1`부터 `mep8`까지만 사용한다.
- 각 MEP policy는 `init`, `mid`, `final` checkpoint로 나눠 최종 fixed partner `8 x 3 = 24`개를 만든다.
- VAE dataset은 이 24개 MEP partner rollout으로 만든다.
- adaptive policy는 `04_train_gamma_s2_risky.sh`에서 VAE partner를 상대로 `gamma_adaptive`를 학습한다.
- 최종 논문용 score는 `06_eval_gamma_risky.sh`에서 기존 Risky evaluation pipeline의 sparse score로 산출한다.

## 전체 흐름

1. `00_check_env.sh`
   - GAMMA transplant import, Risky env adapter, 경로 설정을 확인한다.

2. `01_prepare_gamma_population.py`
   - `transplant/results/RiskyOvercooked/<layout>/mep/mep-S1/wandb/latest-run/files`에서 MEP checkpoint를 읽는다.
   - `mep1`부터 `mep8`까지만 source로 사용한다.
   - 각 policy에서 `init`, `mid`, `final` checkpoint를 fixed partner로 만든다.
   - `mep9`부터 `mep12`는 존재해도 GAMMA source에 넣지 않는다.
   - `gamma/source/population.yml`, `gamma/s2/train.yml`, `gamma/s2/eval.yml`을 생성한다.

3. `02_create_gamma_dataset.sh`
   - fixed MEP partners를 실제 Risky env에서 플레이시켜 VAE 학습용 trajectory를 수집한다.
   - 이 단계는 학습이 아니라 rollout 저장 단계다.
   - full 기준 `GAMMA_TOTAL_TRAJECTORIES=100000`을 사용한다.
   - smoke에서는 명시적으로 작은 값으로 override한다.

4. `03_train_gamma_vae.sh`
   - HDF5 dataset의 `train` group을 사용해 GAMMA VAE를 학습한다.
   - policy-level heldout은 기본으로 쓰지 않는다.
   - VAE validation은 trajectory-level split으로 처리한다.

5. `04_train_gamma_s2_risky.sh`
   - GAMMA의 adaptive coordinator인 `gamma_adaptive`를 학습한다.
   - 이 단계가 최종 adaptive policy를 만드는 핵심 학습 단계다.
   - VAE partner의 latent `z`는 기본 `normal_gaussian`에서 샘플링한다.
   - coordinator 학습 reward에는 handoff shaping을 반영하기 위해 `HANDOFF_SHAPING=1`을 기본값으로 둔다.

6. `05_extract_gamma_s2_risky.py`
   - 학습된 `gamma_adaptive` actor를 평가용 policy pool 형태로 추출한다.

7. `06_eval_gamma_risky.sh`
   - `gamma_adaptive`를 MEP partner들과 양방향으로 평가한다.
   - 최종 논문용 score는 `eval_ep_sparse_r` 기반의 sparse score다.
   - final eval에서는 handoff shaping을 기본으로 켜지 않는다.

## source population 기준

GAMMA Risky baseline의 source는 MEP-only다.

- 기본 source root:
  - `GAMMA_MEP_SOURCE_ROOT=/home/isl_jhoh/CoRL/transplant/results`
- 기본 run:
  - `GAMMA_MEP_RUN_NAME=latest-run`
- 기본 최대 MEP policy 수:
  - `GAMMA_MEP_MAX_POLICIES=8`
- source checkpoint 위치:
  - `transplant/results/RiskyOvercooked/<layout>/mep/mep-S1/wandb/latest-run/files`
- 최종 fixed partner 수:
  - `mep1_init`, `mep1_mid`, `mep1_final`
  - ...
  - `mep8_init`, `mep8_mid`, `mep8_final`
  - 총 24개

사용하지 않는 것:

- human trajectory
- BC human proxy
- SP/FCP heldout
- `mep_adaptive`
- `hsp_adaptive`
- `gamma_adaptive`를 source fixed partner로 사용하는 것
- `mep9`, `mep10`, `mep11`, `mep12`

`gamma_adaptive`는 `gamma/s2/train.yml`에 trainable policy로만 들어간다.

## VAE dataset / VAE 학습 기준

full baseline의 dataset 규모는 100K다.

- `GAMMA_TOTAL_TRAJECTORIES=100000`
- 원본 GAMMA repo의 MEP/all-layout script도 `--total_trajectories 100000`을 사용한다.
- smoke run만 `GAMMA_TOTAL_TRAJECTORIES=2` 같은 작은 값으로 명시 override한다.

VAE 기본 hyperparameter:

- `z_dim=16`
- `vae_hidden_size=256`
- `vae_chunk_length=100`
- `vae_epoch=500`
- `vae_batch_size=64`
- `vae_init_kl_penalty=0.01`
- `vae_kl_penalty=1.0`
- `vae_encoder_input=partner_obs`
- `weight_decay=1e-4`
- `dataset_validation_ratio=0.3`

현재 구조:

- `03_train_gamma_vae.sh`는 `--weight_decay "${GAMMA_WEIGHT_DECAY}"`를 명시적으로 넘긴다.
- `GAMMA_WEIGHT_DECAY` 기본값은 `1e-4`다.
- policy-level heldout은 기본으로 만들지 않는다.
- HDF5 `test` group이 없어도 VAE 학습은 진행되어야 한다.
- heldout eval은 test group이 있을 때만 optional로 수행한다.

## coordinator 학습 / final eval 기준

`04_train_gamma_s2_risky.sh`가 `gamma_adaptive`를 실제로 학습시키는 단계다.

full coordinator 학습 기본값:

- `NUM_ENV_STEPS=150000000`
- `N_ROLLOUT_THREADS=200`
- `REWARD_SHAPING_HORIZON=100000000`
- `PPO_EPOCH=15`
- `NUM_MINI_BATCH=1`
- `EPISODE_LENGTH=200`
- `GAMMA_VAE_Z_GENERATOR=normal_gaussian`
- `HANDOFF_SHAPING=1`

handoff shaping 기준:

- `04_train_gamma_s2_risky.sh`에서는 reward가 RL objective에 직접 들어가므로 handoff shaping을 기본 on으로 둔다.
- `06_eval_gamma_risky.sh`는 최종 sparse score 평가 단계이므로 handoff shaping을 기본 on으로 두지 않는다.
- `common.sh`의 기본값은 `HANDOFF_SHAPING=0`이고, `04`만 stage-specific default로 `1`을 설정한다.

final eval 기준:

- `06_eval_gamma_risky.sh`는 `transplant.eval_risky_hsp`를 재사용한다.
- score CSV에는 `eval_ep_sparse_r`가 `episode_sparse_score`로 기록된다.
- shaped score나 handoff-shaped reward는 최종 논문용 score가 아니다.

## Risky env 호환 확인

action index:

- Risky action order는 `[NORTH, SOUTH, EAST, WEST, STAY, INTERACT]`다.
- 따라서 `STAY` index는 `4`다.
- VAE trainer의 `meaningful_action_mask = (pi_targets != 4)`는 현재 Risky action mapping과 맞는다.

observation shape:

- Risky observation은 MEP policy, VAE dataset, coordinator 학습에서 같은 adapter를 통해 생성되어야 한다.
- 확인된 shape:
  - `risky_dualpath_subgoal`: obs `(7, 5, 28)`, share obs `(7, 5, 56)`
  - `risky_mixed_coordination_subgoal`: obs `(8, 7, 28)`, share obs `(8, 7, 56)`
  - `risky_multipath_subgoal`: obs `(7, 6, 28)`, share obs `(7, 6, 56)`
- MEP actor checkpoint의 CNN input channel도 현재 Risky obs channel `28`과 맞는 것으로 확인했다.

수행한 smoke/정적 검증:

- `bash -n`으로 주요 shell script 문법 확인.

- `human_biased` z generator는 human data가 필요하므로 unsupported error를 내도록 확인했다.

## 결정 사항과 교정 기록

1. GAMMA Risky는 MEP-only baseline으로 둔다.
   - human data, BC proxy, SP/FCP heldout은 이번 baseline에서 제외한다.
   - 논문/repo의 human 관련 branch를 Risky baseline에 억지로 가져오지 않는다.

2. MEP source는 `transplant/results`의 최신 MEP S1 산출물을 쓴다.
   - 현재 사용할 대상은 handoff shaping이 적용된 MEP latest-run이다.
   - 사용자가 해당 run을 더 이상 수정하지 않는다고 확인했으므로 latest-run을 source로 둔다.

3. MEP policy는 8개만 사용한다.
   - source directory에 `mep12`까지 있어도 GAMMA source는 `mep1`부터 `mep8`까지만 사용한다.
   - 최종 source partner pool은 24개다.

4. full dataset trajectory 수는 100K다.
   - 이전에 smoke 편의값 `1000`을 default처럼 둔 것은 잘못이었다.
   - 현재는 `common.sh`와 Python parser default 모두 `100000`으로 교정했다.
   - smoke는 반드시 명시 override로만 작게 돌린다.

5. handoff shaping은 `04` 학습에만 기본 on이다.
   - adaptive policy를 학습시키는 핵심 단계는 `04_train_gamma_s2_risky.sh`다.
   - final eval의 sparse score에는 handoff shaping을 기본으로 섞지 않는다.

6. HSP repo/env 설정을 GAMMA에 임의로 물려받지 않는다.
   - `transplant.eval_risky_hsp` 같은 기존 Risky evaluation utility를 재사용하는 것은 괜찮다.
   - 그러나 HSP env, HSP human/heldout 가정, HSP-specific pool 구성은 GAMMA baseline의 기본값으로 가져오지 않는다.
   - 앞으로 baseline 이식 시 원본 repo/paper 설정과 Risky protocol을 먼저 확인하고, 다른 baseline의 편의 설정은 명시 근거가 있을 때만 사용한다.

## 주의 사항

- `02_create_gamma_dataset.sh`는 학습 단계가 아니다. policy rollout을 HDF5로 저장하는 단계다.
- VAE 학습은 reward를 직접 쓰지 않는다. handoff shaping은 VAE 학습 자체에는 필요하지 않다.
- `04_train_gamma_s2_risky.sh`는 adaptive RL 학습 단계이므로 reward 설정이 성능에 영향을 준다.
- `06_eval_gamma_risky.sh`의 논문용 score는 sparse score다.
- action index `4`가 계속 `STAY`인지 Risky action list가 바뀔 때마다 확인해야 한다.
- layout이 새로 추가되거나 observation feature가 바뀌면 MEP policy obs shape, VAE dataset obs shape, coordinator obs shape가 모두 같은지 다시 확인해야 한다.
- `human_biased` / `human_biased_std` z generator는 이번 MEP-only baseline에서 지원하지 않는다.
