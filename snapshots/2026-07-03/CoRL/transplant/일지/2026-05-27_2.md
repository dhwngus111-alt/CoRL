## Risky multipath subgoal GIF 확인 스크립트 추가

### 배경

`risky_multipath` 계열 layout 중 subgoal `G`가 포함된 버전을 빠르게 눈으로 확인할 필요가 있었다. 기본 `risky_multipath`는 `G`가 없고, subgoal 포함 버전은 별도 layout으로 존재한다.

확인한 layout:

```text
risky_multipath_subgoal
risky_multipath_subgoal_tomato
```

두 layout 모두 `subgoal_disable_steps: 20`을 갖고 있으며, agent가 `G` 타일 위에서 `INTERACT`하면 연결된 puddle `W`들이 일정 step 동안 비활성화됐다가 다시 활성화되는 구조다.

### 수정 내용

`transplant/scripts/render_risky_subgoal_gif.py`를 추가했다.

이 스크립트는 학습 policy 없이 짧은 scripted trajectory만 사용한다.

동작 순서:

1. 지정한 layout을 `OvercookedGridworld.from_layout_name(...)`으로 로드한다.
2. 시작 위치 기준으로 `G`에 인접한 agent를 찾는다.
3. agent를 `G` 위로 이동시키고 `INTERACT`를 실행한다.
4. 이후 `STAY` action을 몇 step 유지하면서 `W`가 사라졌다가 돌아오는 장면을 GIF로 저장한다.

기본 실행:

```bash
/home/isl_jhoh/miniconda3/envs/corl/bin/python transplant/scripts/render_risky_subgoal_gif.py
```

tomato variant 실행:

```bash
/home/isl_jhoh/miniconda3/envs/corl/bin/python transplant/scripts/render_risky_subgoal_gif.py --layout risky_multipath_subgoal_tomato
```

## Risky multipath subgoal HSP 학습 확장

### 배경

`risky_multipath_subgoal` layout에서 agent가 `G` 타일 위에서 `INTERACT`하면 puddle `W`가 일정 step 동안 비활성화된다. 그러나 이 interaction은 기존 `events_infos`에 raw event로 남지 않았기 때문에, HSP Stage 1의 hidden utility weight가 이 행동에 대한 선호를 직접 학습할 수 없었다.

따라서 `subgoal_activated` event를 Risky raw event와 transplant hidden utility schema에 추가했다.

### 수정 내용

Risky engine:

- `risky/src/risky_overcooked_py/mdp/overcooked_mdp.py`
  - `EVENT_TYPES` 끝에 `subgoal_activated`를 추가했다.
  - `resolve_interacts()`에서 agent가 현재 `G` 위에 있고 `INTERACT`를 누르면 `events_infos["subgoal_activated"][player_idx] = True`를 기록한다.
  - 의미는 "실제 물 상태 변화가 처음 발생했는지"가 아니라 "G subgoal interaction이 발생했는지"다. 이미 puddle이 비활성화된 상태에서 다시 누르는 것도 event로 센다.

transplant hidden utility:

- `transplant/hsp_hidden_utility.py`
  - `RISKY_SUBGOAL_EVENT_KEYS = ("subgoal_activated",)`를 추가했다.
  - `RISKY_MULTIPATH_EVENT_KEYS`를 risked + handoff + subgoal로 확장했다.
  - `build_hsp_w0_spec()`에 `subgoal_spec` 인자를 추가했다.
  - CLI에 `--subgoal-spec`를 추가했다.

기본 weight spec:

```text
subgoal_activated index: 29
hidden utility dim: 30
full weight dim: 31
w0 subgoal spec: r[0:3:2]
w1 subgoal spec: 0
w0 sparse spec: r[0:1:2]
w1 sparse spec: 1
```

즉 HSP S1에서 `w0` agent는 `subgoal_activated` weight를 `{0, 3}` 중 하나로 샘플링하고, `w1` agent는 subgoal event에 중립이다.

transplant adapter / pipeline:

- `transplant/adapters/risky_overcooked_env.py`
  - 기존에는 `layout_name == "risky_multipath"`만 허용했지만, 이제 adapter-level allowlist를 제거했다.
  - 앞으로 `risky_multipath_subgoal`, `risky_multipath_subgoal_tomato`, 또는 새 Risky layout이 추가되어도 Risky layout loader가 source of truth가 된다.
- `transplant/scripts/06_greedy_select_risky.py`
  - `--eval-result-dir` 기본값을 고정 `risky_multipath`가 아니라 `TRANSPLANT_ROOT / "biased_eval" / args.layout`로 계산하게 바꿨다.
- `transplant/smoke_check.py`
  - `LAYOUT` 환경변수 또는 `--layout` 인자를 받도록 수정했다.

### 학습 실행 명령

HSP Stage 1 full run은 `TIME_COST=-0.3`를 반드시 명시해서 실행한다. `common.sh` 기본값은 `0.0`이므로, 학습용 step penalty를 의도대로 넣으려면 shell 환경변수로 넘겨야 한다.

```bash
cd /home/isl_jhoh/CoRL

LAYOUT=risky_multipath_subgoal \
TIME_COST=-0.3 \
CUDA_VISIBLE_DEVICES=3 \
SEED_MAX=36 \
NUM_ENV_STEPS=10000000 \
N_ROLLOUT_THREADS=100 \
HSP_FINAL_GIF_EPISODES=3 \
bash transplant/scripts/03_train_hsp_s1_risky.sh
```

```bash
cd /home/isl_jhoh/CoRL
```
