- 사용자가 원하는 것은 `SMOKE`처럼 환경 길이와 seed 수까지 왜곡하는 dry-run이 아니라, **HSP 원본 실행 조건은 보존하되 학습 step만 줄인 normal pipeline 검증**이었기 때문임.
- Greedy Selection은 event feature가 부족하면 조용히 fallback하면 안 되고, 실패가 즉시 드러나야 이후 policy selection 신뢰성이 유지됨.
- HSP hyperparameter를 따르더라도 event schema는 Risky 환경 고유 구조를 따라야 하므로, HSP old/new의 12/21개 event weight로 맞추지 않도록 명확히 경계를 세움.

### 🔹 기존 환경인 HSP에서는 어떤 것을 사용하거나 수정했는가
- HSP repo의 `eval_events.sh` 설정인 `100 eval episodes / 100 eval rollout threads`를 Greedy Selection event evaluation 전용으로 반영함.
- HSP parser 기본 eval 값인 `n_eval_rollout_threads=1`, `eval_episodes=32`를 non-greedy eval fallback 기준으로 반영함.
- HSP 원본 stage별 training knob인 `ppo_epoch=15`, `reward_shaping_horizon`의 S1/S2 차이를 transplant 스크립트에 반영함.
- HSP 원본 repo 파일은 이번 항목에서 추가 수정하지 않음.

### 🔹 기존 환경인 risky에서는 어떤 것을 사용했는가
- Risky dynamics, layout, reward event 판정, `EVENT_TYPES`를 그대로 source of truth로 유지함.
- Risky event 개수는 **38개**로 확인했으며, sparse reward weight까지 포함한 HSP hidden utility 길이는 **39차원**으로 유지함.
- `risky/**` 원본 파일은 수정하지 않음.
